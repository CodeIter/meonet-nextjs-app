# What is Next.js

## Introduction

Next.js is a popular React-based framework that gives you powerful features
such as server-side rendering, static site generation, routing, and more. It’s
developed by Vercel and has matured significantly over time.

In this post we’ll cover:

* Why you might choose pnpm as your package manager
* How the App Router in Next.js works and what benefits it brings
* A quick walkthrough of getting started
* Some best practices and tips

---

## Why use PNPM instead of npm or Yarn?

Using pnpm has several advantages when working with Next.js projects:

* pnpm uses a **content-addressable filesystem** and hard links for duplicated packages, which means faster installs and less disk space usage.
* It enforces a non-flat `node_modules` structure which means fewer “phantom dependency” issues and more predictable installations.
* The official Next.js documentation recommends pnpm as one of the supported package managers.

### Example: Creating a new Next.js project using pnpm

In your terminal you can run:

```bash
pnpm create next-app@latest my-next-app
cd my-next-app
pnpm dev
```

## What is the App Router in Next.js?

The App Router (“new routing system”) is a modern way Next.js manages routes,
layouts, data fetching and server/client components. Some of its key features:

* Instead of pages only, you have an `app/` directory (or `src/app/`) that can contain nested layouts and pages.
* It supports React Server Components which allow part of your component tree to run on the server and stream data to the client.
* Better built-in support for layout sharing, nested routing, and data fetching strategies.

### Basic folder structure

When you create a project with App Router enabled, you’ll get something like:

```
my-next-app/
├── .gitignore
├── README.md
├── eslint.config.mjs
├── next.config.ts
├── package.json
├── postcss.config.mjs
├── public
│   ├── file.svg
│   ├── globe.svg
│   ├── next.svg
│   ├── vercel.svg
│   └── window.svg
├── src
│   └── app
│       ├── favicon.ico
│       ├── globals.css
│       ├── layout.tsx  ← root layout with <html><body>
│       └── page.tsx    ← root page
└── tsconfig.json
```

Here, `layout.tsx` serves as the wrapper for routes, while each `page.tsx`
corresponds to a route automatically.

## Getting Started: Step-by-Step

1. Ensure you have Node.js installed (current LTS).
2. Install pnpm globally if you don’t yet:

   ```bash
   npm install -g pnpm
   ```


3. Create your project:

   ```bash
   pnpm create next-app@latest your-app-name
   cd your-app-name
   pnpm dev
   ```

4. Explore the `app/` directory and try creating a new route:

   ```text
   app/
     └── blog/
         └── page.tsx  ← becomes `/blog`
   ```
5. Build and deploy:

   ```bash
   pnpm build
   pnpm start
   ```

   With pnpm workflows being the same scripts as npm/yarn but faster and more efficient.

## Why choose this combination (Next.js + pnpm + App Router)?

* **Performance & developer experience**: pnpm speeds up dependency installs; Next.js App Router gives modern and efficient routing and rendering.
* **Scalability**: The App Router’s nested layouts and server components help large apps stay manageable.
* **Clean architecture**: Using App Router encourages structure (layout, page, server/client separation) from day one.
* **Better defaults**: Next.js CLI now recommends App Router; pnpm is officially supported.

---

## Best Practices & Tips

* Use the `app/` directory only (or with `src/app/`) to fully leverage the App Router. Avoid mixing old `pages/` unless you need older behavior.
* Take advantage of server components for data fetching and reduce client bundle size.
* If you migrate an older project: follow the official upgrade guide (for example, from Next.js version 14 → 15) for compatibility.
* Ensure your CI/CD tooling supports pnpm (cache, install commands) to reap the performance benefits. Some deployment platforms may need adjustments.
* Keep your `pnpm` workspace and lockfile consistent across environments for reproducible builds.
* Monitor third-party packages: with the App Router you may encounter components not yet optimized for server/client boundaries.

## Conclusion

Combining Next.js (with its powerful App Router) and pnpm (for efficient
package management) gives you a modern, performant, and scalable stack for
building web applications. Whether you’re starting a new project or upgrading
an existing one, using these together sets you up for clean architecture,
faster builds, and a smoother developer workflow.
